# ADR-0003: Канонический журнал и обработка reorg

- Статус: принят (дизайн; реализация в следующих этапах)
- Дата: 2026-11-11

## Контекст

События `processed` и `confirmed` могут быть заменены, поток может оборваться, а RPC и Yellowstone имеют разные окна retention.

## Решение

Сырой append-only журнал хранит `(slot, blockhash, parent_slot, commitment, source, payload_hash)`. Проекции строятся отдельно и могут быть пересчитаны. `processed` используется только для низколатентных предварительных решений; бухгалтерское состояние и окончательный outcome закрепляются на `finalized`. При fork/dead slot все производные записи ветки помечаются orphaned и компенсируются. Checkpoint двигается в одной транзакции с записью событий. Backfill идёт RPC-диапазонами от последнего finalized checkpoint и сходится с live stream идемпотентными ключами.

## Последствия

Хранилище и логика сложнее, зато восстановление детерминировано. Нельзя считать Redis источником истины или подтверждать сделку только по WebSocket-уведомлению.
